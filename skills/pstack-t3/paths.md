# Paths in T3 Code

Read this before a step uses a `.cursor/` path, a store, a tracker, a transcript, or a pstack path or URL. The names map as in [the T3 Code adapter](SKILL.md).

| Cursor | T3 Code |
| --- | --- |
| `.cursor/skills/`, `~/.cursor/skills/` | `.agents/skills/`, `~/.agents/skills/`. Codex and Pi read those. Claude reads `.claude/skills/` and `~/.claude/skills/`. Write a new project skill to `.agents/skills/<name>/`, then link it for Claude threads with `ln -s ../../.agents/skills/<name> .claude/skills/<name>`. |
| `~/.cursor/plugins/`, `.cursor-plugin/plugin.json` | `<skills>`. pstack's version is in `<skills>/pstack-t3/pstack.json`. |
| `plugins/cache/` | The installed pstack skills in `<skills>`. Never edit one, because the next install rewrites it. Copy the skill to the project's `.agents/skills/<skill>/` and edit the copy. If that path is a link into the installed pack, which `./install.sh --project` makes, replace the link with a real copy first. `~/.agents/skills/<skill>/` and `~/.claude/skills/<skill>/` are the installed skill itself, so never copy there. |
| `.cursor/rules/*.mdc`, always-applied rules | The repo's `AGENTS.md`, or `CLAUDE.md` when the repo keeps its rules there. The model rule is the exception. See Models in [Spawning subagents in T3 Code](spawning.md). |
| `.cursor/worktrees/` | The worktrees `git worktree list` shows. T3 Code keeps the ones it makes in its own folder, usually `~/.t3/worktrees/<project>/`. `t3_worktree_status` reports this thread's worktree. `t3_worktree_list` gives a thread's branches and checkout paths, but leaves out detached worktrees. |
| A bundled script that reads `~/.cursor/` | Trust only its git columns. `poteto-mode/scripts/worktree-audit.sh` reads chat age from Cursor transcripts, so in T3 its chat column is empty and a `safe` bucket is unproven. Prove it with threads. A T3 thread keeps its worktree after its run ends. List the project's threads with `t3_thread_list` and `includeSubagents: true`, and read each with `t3_thread_read` for its `worktreePath`. Never remove a worktree that a thread uses, unless that thread is archived or the operator names the worktree. |
| The current agent's store (path in the system prompt) | `~/.agents/pstack-store/<repo-slug>/`. Create it. |
| The Project store | `~/.agents/pstack-store/<repo-slug>/projects/<project-slug>/`. Create it. A worktree child can read it, because it sits outside every checkout. Only the coordinator writes it. |
| The Project tracker (`notes.md`) | `notes.md` in the Project store. T3 has no tracker of its own. Keep each worker's `taskId`, `childThreadId`, branch, PR, and verdict there, so a restart or a new coordinator thread can pick the program up. |
| `pstack/skills/<path>` in a command, or `git show origin/main:pstack/skills/<path>` | `<skills>/<path>`, as an absolute path. The installed tree is the trunk copy, so read it with `cat`. Keep `git show origin/main:` for files in the working repo, such as a project verification skill or `AGENTS.md`. A plan needs at least one such line, because `check-plan.mjs` looks for it. |
| `https://github.com/cursor/plugins/blob/main/pstack/<path>` | The local copy when this tree ships it: `<skills>/<name>/` for skills, `<skills>/pstack-t3/guide/` for `docs/guide/`, `<skills>/pstack-t3/README.md`, `<skills>/pstack-t3/agents/`. Read it and never fetch it. Give the user the URL when they need a link. |
| Transcripts in `~/.cursor/projects/<slug>/agent-transcripts/` | T3 threads. Find a top-level thread with `t3_thread_search` or `t3_thread_list`. `t3_thread_search` skips subagent threads, so find a child with `t3_thread_list` and `includeSubagents: true`, or by the `childThreadId` you recorded. Read one with `t3_thread_read`, `view: "messages"` for the conversation or `"activity"` for tool calls. A delegated child's transcript is its `childThreadId`. A thread's last activity, not a file mtime, says whether it is live. Cite a thread by the `link` that its tool result gives, copied as it is. Stay in this project, as the skills' rule against globbing across `~/.cursor/projects/*/` says. Omit `projectId`, so both tools use the calling thread's project, and never read another project's threads unless the user asks. `t3_thread_search` filters the app's global top matches to one project, so it can return fewer than `limit`. For a full sweep of a time window, page through `t3_thread_list`. |
